# VoDog services

First-party code is licensed under AGPL-3.0; see the repository license. Third-party libraries retain their own licenses and attribution. This source distribution contains no credentials, recordings or deployment state. Example domains and documentation IPs are placeholders. Node IDs are `relay-primary` and `relay-secondary`.

## Build and test

Use Node.js 22 or newer, npm, Go matching each `go.mod`, PostgreSQL 17 for database tests, and FFmpeg for recording conversion tests. Native voice audio uses `@roamhq/wrtc`; verify its support for your runtime and platform.

Run from each service directory:

| Directory | Commands |
| --- | --- |
| `control` | `npm ci`, `npm run build`, `npm test` |
| `voice` | `npm ci`, `npm test` |
| `media` | `go test -race ./...`, `go build ./...` |
| `recording-archive-validator` | `go test -race ./...`, `go build -o /tmp/vodog-recording-archive-validator .` |

Control tests require three **separate disposable** databases supplied as `TEST_DATABASE_URL`, `REPLAY_TEST_DATABASE_URL`, and `REPLAY_MIGRATION_TEST_DATABASE_URL`. Database names must contain `test`; suites rebuild schemas. Never use application databases. The complete suite fails fast when the required database URLs are absent. Two Control tests exercise shared infra helpers (`infra/s33-fixture-safety.js`, `infra/control_code_recovery_gate.py`) and require those files in the complete repository. Cross-service tests also need the sibling voice/validator sources.

Live provider, remote TURN, browser, Pixel and native bridge probes are opt-in. Do not enable them in ordinary unit-test runs. Synthetic audio inputs are generated by the operator; no real recordings ship here.

## Control runtime

Export environment variables explicitly, then run `npm run migrate` and `npm start` in `control`. Start with `control/.env.example`; no script loads the repository root `.env` automatically. `src/config.ts` is the complete validated configuration reference.

Required: `DATABASE_URL` and a random `COOKIE_SECRET` of at least 32 characters. Set `PUBLIC_ORIGIN` and `RP_ID` to your HTTPS origin and relying-party domain (defaults are `vodog.example.com`). `PORT` defaults to 3100. Seeding is explicit through `TEST_USERNAME`, `TEST_PASSWORD`, optional `TEST_USER_ROLE`, and optional `SEED_GATEWAY_ID`/`SEED_GATEWAY_TOKEN`; no account is shipped.

- Media: set `MEDIA_NODES_JSON` and `MEDIA_DEFAULT_NODE_ID`. Each node supplies `id`, `controlBaseUrl`, `turnUdpUrl`, `turnTlsUrl`, `mediaSecret`, `turnSecret`; optional `probeUrl` enables probes. Alternatively supply `MEDIA_SECRET`/`TURN_SECRET` for the single-node defaults, replacing the example TURN endpoint. Secrets need at least 32 characters. Optional relay routing requires `MEDIA_RELAY_TURN_TLS_URL`, `MEDIA_RELAY_TURN_HOSTNAME`, and `MEDIA_RELAY_NODE_ID` together.
- AI: `AI_ENABLED`, `AI_WORKER_READY`, `AI_INTERNAL_TOKEN`, `AI_VOICE_PROVIDERS` and optional `AI_MEDIA_NODE_ID`. Keep tokens separate from device, media and user credentials.
- Push: Apple requires `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_KEY_PATH`. Android requires `FCM_ENABLED=true`, `FCM_PROJECT_ID`, `FCM_CREDENTIALS_PATH`. Generate your own signing keys and configure `ANDROID_PASSKEY_ORIGINS`. Bundle/package identifiers are `org.vodog` and APNs VoIP topic `org.vodog.voip`.
- Recordings: configure `RECORDING_ROOT`; optional `RECORDING_MP3_CACHE_DIR` and `RECORDING_BACKUP_ROOT`. Pixel archive support requires `PIXEL_ARCHIVE_ENABLED=true`, `PIXEL_ARCHIVE_ROOT`, and `PIXEL_ARCHIVE_VALIDATOR_PATH`. Paths requiring absolute form are validated at startup; supply paths from your own deployment.
- Transcription: `TRANSCRIPTION_ENABLED=true`, `TRANSCRIPTION_ENABLED_AT` (ISO timestamp watermark), `TRANSCRIPTION_API_KEY`, `TRANSCRIPTION_MODEL`; optionally `TRANSCRIPTION_BASE_URL` and `TRANSCRIPTION_FALLBACK_MODEL`. Report enrichment uses `REPORT_AI_BASE_URL`, `REPORT_AI_API_KEY`, `REPORT_AI_MODEL` together. These can incur provider charges.
- Turnstile: `TURNSTILE_ENABLED=true`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`.

Schema migrations and API payloads are retained together with their tests. Legacy `CC_*` diagnostic environment names and binary protocol markers remain protocol identifiers, not deployment identities.

## Media runtime

Set `MEDIA_SECRET` (at least 32 bytes), `TURN_SECRET`, `MEDIA_NODE_ID`, and `MEDIA_TURN_UDP_URL` (explicit `turn:host:port?transport=udp`). Set `MEDIA_LISTEN_ADDR` (default `127.0.0.1:16881`), `MEDIA_RECORD_DIR` (default `./data/recordings`), and `MEDIA_PROBE_ALLOWED_ORIGINS` as needed. Keep internal listeners private. The example secondary-node fallback cannot provide a working relay; configure your own TURN endpoint. Diagnostic `CC_MEDIA_*` controls are optional and validated in source.

## Voice runtime

See [voice configuration](voice/README.md). Use `node server.mjs` with explicit environment. The worker's configured Control origin must match your actual Control port. Off-loopback Control requires HTTPS; no private Docker-network plaintext exception ships in VoDog.

## Archive validator

See [validator usage](recording-archive-validator/README.md). Control calls this local executable; it has no network listener and needs no secrets.

CN phone-parser fixtures are synthetic, format-valid samples used only in disposable tests; they are not dial targets or claims that a number is unallocated. Provider IDs, keys and device tokens in tests are deterministic synthetic values or generated at runtime.
