# 架构与数据流

[文档目录](README.zh-CN.md) · [English](architecture.md)

## 职责

Control 是唯一状态权威：认证用户与网关、分配 SIM、仲裁通话归属、下发命令与短信、存储联系人和黑名单，并协调录音、转录、报告和 AI 租约。PostgreSQL 保存业务状态。客户端不直连数据库，也不能绕过服务端操作远端 SIM。

网关负责把命令转换为真实电话操作并上报观察结果。Pixel 使用 Android Telecom / InCallService 与特权音频采集、注入；DJI 网关通过 macOS 集成控制模组 AT 接口和 USB 音频。电话、短信、媒体分别报告就绪状态；有心跳不代表音频可用。

Go/Pion 媒体桥提供 gateway 与 client 角色。网关使用 `cellular-opus-v1` 数据通道，客户端与 AI worker 使用 WebRTC 媒体。coturn 是独立中继服务，Control 签发短期媒体授权与匹配传输类型的 TURN 配置。仅有 STUN 不满足本系统的 relay-only 设计。

## 远程通话

1. 登录后的客户端选择已分配 SIM 发起通话，或认领来电。
2. Control 检查归属、网关就绪与设备占用，再下发命令。
3. 网关执行、确认，并上报真实电话状态。
4. 选定的媒体节点连接网关与获得控制权的客户端。界面状态不能授权重复接听或拨号。
5. 挂断请求与物理状态通过 Control 对账；媒体失败或旧占用不能直接当作成功结束。

同一 Pixel 中有多张 SIM，不代表可以同时进行多路独立音频通话。每块模组也是一个物理通话资源。其他客户端必须尊重服务端归属，包括已在别处接听的通话。

## 本机通话与短信

启用对应功能门后，Pixel 本机拨出的电话可同步记录与被动录音归档。macOS 可选本机已连接模组，通过 Mac 麦克风、扬声器和模组 USB 音频直拨，不经过远程媒体桥；共享归档仍需要网关配对及采集绑定。本机通话成功不代表绑定或上传成功。

短信采用持久队列与明确结果。超时可能意味着模组已发送、但确认丢失；`unknown` 不能盲目重发。长短信后续分段可补全既有消息。本机短信观察同步与通过 Control 发送是两条不同路径。

## 身份与恢复合同

网关凭据具有 epoch；命令和事件包含 generation 与归属上下文。SIM 身份不能用卡槽、显示号码或临时 Android subscription ID 代替，拔卡、迁移和重新分配时都必须保留归属检查。

Pixel 防重账本用于防止旧命令再次执行。不能通过清账本、降低 floor、恢复旧数据库或伪造完成状态来消除就绪错误。DJI 采用自己的命令日志与接入时间保护，不能宣称具备同一套 Pixel replay-horizon 能力。

删除通话涉及记录、录音、归档上传及 worker 的一致生命周期，不等于任意删除目录。本地导出、独立录音器、诊断和备份各有独立保留责任。

## 源码导航

`services/control/src` 保存 API、schema 与配置合同；`services/media` 负责传输与服务端录音；`services/voice` 负责供应商和 worker 生命周期；`apps/android/gateway` 实现 Pixel 执行；`apps/macos` 实现模组行为。各平台客户端位于对应 `apps` 子目录。命名或工具版本与示例不同时，以实际导出源码及依赖清单为准。
